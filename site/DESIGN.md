# Website design: the cyanotype drafting sheet

The site (`site/`, published at https://sarthak-47.github.io/crtgrphr/) is one
engineering drawing of a real system: drafted by Cartographer, and live under the
visitor's hand. Product context lives in [`../PRODUCT.md`](../PRODUCT.md).

## Principles

- **Show the map, not adjectives.** Every map on the page is real app output,
  generated by `npm run site:data` (`scripts/site-data.ts`) from the app's own scanner,
  layout engine, Mermaid importer and re-scan diff. The only hand-written model is the
  "Describe" example, and the page labels it as an example.
- **Drafting conventions are the components.** No cards, no feature grid. Detail
  callouts (A, B, C), view captions, a symbol legend, revision clouds and a revision
  table, general notes, a parts list, and a title block that holds the downloads.
- **One highlighter.** Yellow marks only what the visitor touches or should act on:
  the Download button, pinned or dragged boxes, title-block download cells on hover or
  focus (never at rest), focus rings, and the Mermaid edge labels in source listings.

## Tokens (`style.css` `:root`)

| Token | Value | Use |
|---|---|---|
| `--paper` | `#0c2b5b` | The sheet (Prussian blue), also node fills |
| `--paper-deep` | `#071d42` | Deeper exposure, code panels |
| `--ink` | `#eef4ff` | Linework and primary text |
| `--ink-2` / `--ink-3` | 76% / 60% ink | Body text / captions and labels |
| `--rule` / `--rule-soft` | 26% / 13% ink | Table and section rules |
| `--grid` / `--grid-major` | 5% / 8.5% ink | 24px and 120px drafting grid |
| `--hi` / `--hi-ink` | `#ffd23f` / `#1b1500` | The highlighter and text on it |

The sheet also gets two radial gradients for uneven cyanotype exposure and an SVG
`feTurbulence` paper grain (`body::before`, overlay blend). The page is dark only
(`color-scheme: dark`): the blueprint is the identity, not a theme.

## Type

- **Overpass** (Google Fonts) for everything. Headlines 800, tight tracking
  (`-0.035em` on the h1). Functional labels (view names, table heads, title-block
  labels) are uppercase, 0.75–0.8125rem, `0.08em` tracking, like drafting lettering.
- **Overpass Mono** only for code, file names, sublabels inside map boxes, edge labels
  and sizes. Never as decoration.

## Map drawing (`main.js`, `MapView`)

- Shapes by role: database and cache are cylinders (cache gets a second band), queue
  a box with two end bars, frontend a box with a title bar, cloud/proxy a chamfered
  box, decision a diamond, everything else a rounded box.
- Edges are orthogonal, ink at 76%, with filled arrowheads; dashed for async/optional.
  "depends on" labels are hidden (the legend says what an arrow means).
- Layout routes from ELK are used only while both ends still touch their boxes; after a
  drag a simple orthogonal router takes over, mirroring the app.
- Draw-in: a pen-stroke animation (`pathLength=1` dash offset) ordered by layer, when
  a map first enters the viewport. Maps are fully drawn without it; reduced motion
  turns it off.

## View 1 (live)

Drag or arrow-key a box: it pins (yellow outline plus a fixed-support symbol). ELK
0.9.3 is loaded from jsDelivr on first interaction and re-flows the rest with the app's
own options and interactive strategies; overlaps with pinned boxes are pushed across
the flow. Reset restores the generated layout. If ELK cannot load, the box still moves.

## Layout and responsive

- Sheet border with zone references (1–8 across, A… down) drawn by `drawZones()`.
- Hero: copy left, live map right (≈60%); stacks below 1080px.
- Detail views: callout bubble, copy, then source or quote beside it, drawing full width.
- Under 640px: narrower frame, nav reduced to GitHub, full-width buttons, portrait
  (`DOWN`) layouts for Views 1 and 2 (`heroDown`, `rescanDown` in `data.json`), and
  maps scroll sideways at a minimum width so lettering stays legible.

## Don'ts

Gradient text, glass, glow, emoji or icon-grid features, side-stripe accents, invented
numbers (users, stars, downloads), testimonials, a second accent colour.
